# 싱크노트 웹

폰·태블릿·PC 어디서나 같은 노트를. 싱크노트 웹 클라이언트입니다.

## 개발
npm install
npm run dev

## 구조
- auth/ 로그인·세션
- billing/ 요금제·환불 계산
- sync/ 저장·동기화
- upload/ 첨부 파일 제한
- search/ 노트 검색 색인
- editor/ 에디터 확장(표, 태그)
- preview/ 모바일 공용 이미지 미리보기 모듈 (Android)
- server/ 저장 서버 클라이언트

## 환경 변수
`.env.example`을 참고해 `.env.local`을 만듭니다.

- `VITE_SUPPORT_URL`: 모아가 제공하는 `/support/syncnote` 경로를 포함한 **전체 문의 페이지 URL**. 주소가 확정되면 설정하며, 기본값은 비어 있습니다.
- 절대 `http://` 또는 `https://` 주소만 허용하고 사용자명·비밀번호가 포함된 주소는 거절합니다. 경로를 자동으로 덧붙이지 않습니다.
- 미설정 또는 잘못된 주소이면 안내만 표시합니다. 환경 변수 변경 후에는 개발 서버를 다시 시작하거나 배포를 다시 빌드해야 합니다.

## 문의 페이지 연결
오른쪽 아래 **문의하기**를 누르면 모아 문의 페이지를 새 탭에서 엽니다. `noopener,noreferrer`를 적용하며, 싱크노트 안에서 문의를 접수·발송·조회하지 않습니다.

클릭 시점에 다음 파라미터만 구성합니다. 설정 URL의 기존 검색어와 해시는 제거합니다.

| 파라미터 | 값 |
|---|---|
| `cid` | `localStorage['syncnote.customerId']`에 보관된 `U-2000`~`U-2999` 식별자. 기존 값을 재사용하며, 없거나 형식이 다르면 새로 생성 |
| `os` | `getEnv()`가 읽은 현재 브라우저 이름·버전 |
| `app_version` | `web` |
| `error_code` | 최근 30분 안에 기록한 오류 코드. 없으면 파라미터를 생략하며 수신 측은 `null`로 취급 |
| `from` | 싱크노트 페이지의 `origin + pathname`. 검색어·해시·장애 주입 값은 제외 |

이메일·이름은 전송하지 않습니다. 문의 내용·첨부·담당자 답변은 모아 문의 페이지에서 관리합니다. 모아는 `/support/syncnote`의 테넌트와 `cid`를 함께 사용해 기존 상담을 조회하고, 다시 방문한 고객이 답변을 확인할 수 있도록 연결해야 합니다. 이 수신 계약의 구현과 실제 문의 페이지 주소는 모아 측에서 제공해야 합니다.

브라우저 저장소를 지우거나 다른 브라우저를 사용하면 같은 `cid`가 유지되지 않습니다. 이전 위젯의 로컬 문의 데이터는 읽거나 전송하지 않으며 호스팅된 상담으로 자동 이관하지 않습니다.

`cid`는 클라이언트가 바꿀 수 있는 식별자이며 충돌도 가능하므로 인증이나 상담 소유권 증명으로 사용할 수 없습니다. 실서비스에서는 서버가 발급한 서명 토큰 또는 검증된 고객 세션을 사용하고, 수신 서버에서 테넌트·고객·상담 소유권을 확인해야 합니다. URL 파라미터만으로 다른 고객의 상담 조회를 허용해서는 안 됩니다.

## 배포
main에 push하면 GitHub Pages로 배포됩니다.

저장소 **Settings → Secrets and variables → Actions → Variables**에 `SUPPORT_URL`을 등록하면 빌드 시 `VITE_SUPPORT_URL`로 전달됩니다. 아직 주소가 정해지지 않았다면 비워 둡니다. Pages의 Source는 **GitHub Actions**를 사용합니다.
